# Nocturne Studio v1.0.5 — Estável

[English](https://github.com/gustavomfg/nocturne-studio/blob/v1.0.5/docs/releases/v1.0.5.md)

O `v1.0.5` sucede o `v1.0.2` com execução de IA independente de fornecedor,
interface desktop renovada e correções nas conexões, credenciais locais e criação
de tarefas. Não exige SDK da OpenAI, Codex CLI, conta ChatGPT nem assinatura de
fornecedor. O Nocturne Studio continua sendo software livre sob a licença MIT.

## Destaques

- Review, Build e Docs usam o modelo escolhido para cada workspace. Conecte
  Gemini, OpenRouter, DeepSeek, Groq, Mistral ou xAI com sua chave de API, use
  Ollama ou LM Studio localmente, ou configure outro endpoint Chat Completions.
  Uma execução sem modelo associado para com uma mensagem explícita.
- A execução por Provider inclui ferramentas limitadas ao workspace. Review e
  Docs podem ler; Build pode editar arquivos e pedir execução de comandos.
  Comandos exigem aprovação e rodam sem shell. Alterações, diffs e rollback
  protegido continuam visíveis para o desenvolvedor.
- O desktop recebeu superfícies neutras e compactas, nova logo N em pixel art,
  seleção de modos mais clara e indicador do modelo ativo no compositor.
- As configurações mantêm nomes das seções, erros e avisos de descarte visíveis
  em janelas menores. A remoção de conexões controla o foco, aceita Escape e
  permite recuperação de erros; o salvamento bloqueia fechamento acidental.
- Os endereços locais são editáveis. Catálogos grandes têm busca, a descoberta
  de modelos pode ser repetida sem duplicar conexões e a chave sai do formulário
  assim que a conexão é salva.

## Correções de estabilidade

- Conexões remotas usam os endereços IPv4 e IPv6 validados quando uma família
  está inacessível. Validação DNS, exigência de HTTPS e restrições de redirects
  continuam ativas.
- Erros de créditos do OpenRouter e erros recebidos durante streaming são
  informados corretamente, sem concluir a execução como bem-sucedida.
- O startup Linux detecta Secret Service ou KWallet instalados em desktops sem
  seleção nativa de chaveiro. Armazenamento seguro indisponível gera uma mensagem
  com orientação; credenciais em texto simples continuam recusadas.
- Campos internos de ordenação do contexto não invalidam mais a tarefa
  normalizada, corrigindo envios com `TaskBuilderError` quando havia contexto
  do workspace.
- Instruções de Review, persistência de Docs e modelos sem declaração de
  capacidades são tratados de forma consistente. Testes de comandos no Windows
  normalizam caminhos temporários.

`latest-mac.yml` e os manifestos `SHA256SUMS-Windows`, `SHA256SUMS-Linux` e
`SHA256SUMS-macOS`. O Linux tem a assinatura destacada `SHA256SUMS-Linux.sig`,
verificada com a chave pública de release.

Os pacotes Windows e macOS continuam sem assinatura de plataforma, e o macOS
sem notarização, conforme a política existente. A atualização do macOS é manual
pelo DMG; a instalação automática não é suportada. No Linux, o auto-update
suporta AppImage; instalações `tar.gz` exigem atualização manual. Verifique o
manifesto de checksums correspondente antes de instalar.

## Atualização e compatibilidade

- Faça backup dos dados locais antes de atualizar. O schema 32 migra tipos
  legados de Provider, remove configurações e identificadores de thread do CLI
  antigo e preserva histórico, referências de credenciais e decisões de revisão.
  Backups antigos continuam importáveis.
- Identificadores existentes de instalação e a migração do diretório de dados
  legado são preservados para continuidade. Tags e assets históricos publicados
  permanecem preservados.
- Credenciais ficam no processo principal e no armazenamento seguro do sistema,
  fora de backups, diagnósticos e artefatos de release.
- A compatibilidade depende do servidor e modelo. Build precisa de function
  calling; Review e Docs podem repetir sem ferramentas quando o modelo as recusa.
  O adapter atual usa Chat Completions, sem implementar toda API nativa de fornecedor.
- Review continua somente leitura. Comandos rodam com os privilégios do sistema
  do desenvolvedor após aprovação, sem sandbox do sistema operacional. Rollback
  mantém as restrições documentadas e não é uma transação atômica do workspace inteiro.

## Validação da release

O workflow exige CI bem-sucedido de código-fonte, renderer e pacotes das três
plataformas no commit exato da tag. O empacotamento usa runners Linux, Windows e
macOS do GitHub, executa smoke do aplicativo e verifica identidade do updater,
inventário, checksums e assinatura GPG Linux antes da publicação. A verificação
final compara tag remota, notas, tamanhos e SHA-256 dos assets com o build validado.
