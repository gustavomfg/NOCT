# Nocturne Studio v1.0.2

`v1.0.2` follows the published `v1.0.1` stable line.

## Scope since v1.0.1

- Safer rollback on supported Linux local filesystems, Windows NTFS and macOS
  APFS: native capabilities select authorized objects, collisions preserve
  competing data, and unsupported operations are refused without a weaker fallback.
- Clearer recovery and execution results: decisions are completed only after
  filesystem verification, preparation errors finish reserved executions, and
  interrupted operations retain evidence rather than inventing success.
- Vendor-independent execution in every mode through the Provider selected for
  the workspace. Invalid, failed or incomplete Reviews cannot silently resolve
  existing suggestions.
- Validation rechecks workspace/execution authorization immediately before running
  prepared commands. This is authorization enforcement, not an OS sandbox.
- More reliable import-resolution invalidation, conservative context freshness and
  latest-refresh-wins behavior within a renderer session.
- Linux terminal discovery supports installed applications without depending on
  Debian's `x-terminal-emulator`; workspace names are not interpolated into a
  Windows terminal shell command. The editor launcher remains WebStorm-specific.
- Updated schema history through version 32 and refreshed the bundled Electron
  runtime to a patched release, alongside build/test dependency fixes.
- Preserves the local-first model, explicit workspace authorization and
  developer approval boundary.

## Distribution policy

Rollback is not an atomic workspace transaction. Existing regular files and
parents, supported permissions and a 32 MiB file limit define its conservative
subset. Relocating an authorized directory does not revoke an already-issued
syscall; known structural loss prevents further admission. Retained artifacts
and interrupted operations may require manual reconciliation. See
[Protected rollback V1](../native-rollback-v1.md) for exact restrictions.

The configured Linux, Windows x64 and macOS ARM64 targets are the source of
truth for release artifacts. Linux checksum manifests are signed in the
release environment. Windows and macOS artifacts are distributed
with checksums but remain unsigned and not notarized under the current policy.
macOS automatic updates are explicitly unsupported because the native updater
requires a signed application. Upgrade manually using the DMG; preserve local
user data. Metadata/ZIP transport and startup rehearsals are not installer certification.

## Compatibility and publication boundary

No OpenAI CLI, SDK or account is required. Review, Build and Docs use the
user-configured Provider, including local servers. The current adapter uses
the Chat Completions protocol; discovery, streaming and tool compatibility
depend on the selected server and model. See the
[Provider contract](../provider-contract.md).

The stable release workflow requires successful CI for the tagged commit,
cross-platform package smoke, exact asset inventory, updater metadata, Linux
GPG verification and published asset digest checks.
