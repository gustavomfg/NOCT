# Nocturne Studio v1.0.5 — Stable

[Português do Brasil](https://github.com/gustavomfg/NOCT/blob/v1.0.5/docs/releases/v1.0.5.pt-BR.md)

`v1.0.5` follows `v1.0.2` with vendor-independent AI execution, a renewed desktop
interface and fixes for provider connections, local credentials and task creation.
No OpenAI SDK, Codex CLI, ChatGPT account or vendor subscription is required.
Nocturne Studio remains free software under the MIT license.

## Highlights

- Review, Build and Docs use the model selected for each workspace. Connect
  Gemini, OpenRouter, DeepSeek, Groq, Mistral or xAI with your own API key, use
  Ollama or LM Studio locally, or configure another Chat Completions endpoint.
  A run without an assigned model stops with an explicit message.
- Provider execution includes bounded workspace tools. Review and Docs have
  read tools; Build can edit files and request command execution. Commands
  require approval and run without a shell. Changes, diffs and guarded rollback
  remain visible to the developer.
- The desktop has compact neutral surfaces, a new pixel-art N logo, clearer
  mode selection and an active-model indicator in the composer.
- Settings keep section names, errors and discard warnings visible on smaller
  windows. Connection removal supports keyboard focus, Escape and recovery from
  errors; settings cannot close accidentally during a save.
- Local connection addresses are editable. Large catalogs are searchable, model
  discovery can be retried without creating duplicate connections, and API keys
  leave the form immediately after the connection is saved.

## Reliability fixes

- Remote connections can use the validated IPv4 and IPv6 addresses when one
  address family is unreachable. DNS validation, HTTPS requirements and redirect
  restrictions remain enforced.
- OpenRouter credit errors and errors received inside streaming responses are
  reported correctly instead of completing the run as successful.
- Linux startup detects installed Secret Service or KWallet services on desktops
  without native keyring selection. Unavailable secure storage produces an
  actionable error; plaintext credential storage remains refused.
- Internal context-ranking fields no longer invalidate normalized tasks, fixing
  sends that failed with `TaskBuilderError` when workspace context was present.
- Provider Review instructions, Docs persistence and models with undeclared
  capabilities are handled consistently. Windows temporary paths are canonicalized
  in workspace command tests.

## Upgrade and compatibility

- Back up local data before upgrading. Schema 32 migrates legacy provider types,
  removes obsolete CLI settings and thread identifiers, and preserves conversation
  history, credential references and review decisions. Older backups remain importable.
- Existing installation identifiers and the legacy data-directory migration are
  retained for upgrade continuity. Published historical tags and release assets
  are preserved.
- Credentials stay in the main process and operating-system secure store. They
  are excluded from backups, diagnostics and release artifacts.
- Provider compatibility depends on the server and model. Build needs function
  calling; Review and Docs can retry without tools when the model rejects them.
  The current adapter uses Chat Completions rather than every vendor's native API.
- Review stays read-only. Commands run with the developer's OS privileges after
  approval, not inside an OS sandbox. Rollback retains its documented filesystem
  limits and is not an atomic transaction over the whole workspace.

## Release validation

The release workflow requires successful source, renderer and three-platform
package CI for the exact tagged commit. Packaging runs on GitHub-hosted Linux,
Windows and macOS, smoke-tests the application and verifies updater identity,
asset inventory, checksums and the Linux GPG signature before publication.
The final publication check compares the remote tag, release notes, asset sizes
and SHA-256 digests with the verified build.
